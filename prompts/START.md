Objective: Build a local-first, Cloud Run–ready Hybrid Search & RAG service for LinkedIn saved posts exported as JSON from "LinkedIn Saved Post Hero". Multiple exported JSON files are staged in data/*.json for local testing.Stack & Constraints:Python 3.11+ managed with uv, FastAPI, qdrant-client[fastembed], google-genai.Environment variables are already exported via direnv: GEMINI_API_KEY, QDRANT_URL (http://localhost:6333), QDRANT_API_KEY.Use gemini-3.5-flash-lite for structured auto-tagging/summarization and gemini-3.8-flash for RAG synthesis.Core Components:src/db.py: Connect to Qdrant. Create a linkedin_posts collection with named dense (COSINE) and sparse (Modifier.IDF for BM25) vectors via FastEmbed. Create payload indexes before ingestion for author_name (keyword), ai_tags (keyword), has_image (bool), and is_company_post (bool).src/enrich.py: Given post_text, call gemini-3.5-flash-lite with Pydantic structured output to return ai_tags (3–5 normalized lowercase tags) and ai_summary (1–2 sentences).src/ingest.py: Support ingesting either a single JSON file or all data/*.json files via CLI (uv run python -m src.ingest data/). Deduplicate across files and against Qdrant using deterministic point IDs (uuid.uuid5(uuid.NAMESPACE_URL, post_urn)). Pre-check existing IDs in Qdrant and skip already-ingested posts before calling Gemini.src/main.py (FastAPI):POST /ingest: Accepts an uploaded JSON export file and returns {ingested, skipped, failed}.GET /search: Hybrid search using Qdrant prefetch (dense + BM25 sparse) fused with Fusion.RRF, with optional author_name and ai_tags filters.POST /ask: Retrieves top-$k$ hybrid results and calls gemini-3.8-flash to synthesize a cited answer with post_url links.Cloud Run Ready: Include a minimal multi-stage Dockerfile using uv and a .dockerignore.Start by generating the Implementation Plan and directory structure for review before writing code.
